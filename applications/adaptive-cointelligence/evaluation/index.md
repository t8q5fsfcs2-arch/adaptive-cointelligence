## First proposed proof

1. A project records its current framing. An authorized contributor publishes one exact piece of evidence challenging it, after previewing what will be released.
2. The person authorized by current project policy reviews that same evidence, records why the framing changes or does not, and can reload the result with its basis intact.
3. If a successor is created, only work with a documented dependency on the old version is flagged. The original packets and their sources do not change, and unshared material stays private.
4. Repeat with different assignees and the same policy, without changing role names or code. Then change the assignee or evidence mid-review. The old basis must not authorize a write; the newly authorized person can inspect the same permitted evidence. Verify no access leak across project boundaries. Repeat publication to verify it does not create a second commitment.

## Return

Return the observed evidence and identity/version boundaries for each check, including stale and denied cases. If the journey is not installed and exercised, label it untested.
